# Fisga Caching P0+P1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Corrigir o cache privado do service worker e padronizar headers HTTP (P0), depois substituir os caches ad-hoc de condições/geocoding por `HybridCache` do .NET 10 com single-flight, TTL para falha parcial e cache negativo (P1).

**Architecture:** A API passa a ter default `private, no-store` e só cacheia publicamente endpoints marcados com `CachePolicy`. O Astro define `Cache-Control` por rota no middleware, com bypass para cookie nas páginas personalizadas. O service worker separa cache público de privado e limpa tudo no logout. No backend, `HybridCache` (L1 memória) vira a única camada de cache de dados externos; Redis/CDN ficam fora deste plano.

**Tech Stack:** ASP.NET Core 10, `Microsoft.Extensions.Caching.Hybrid` 10.x, Astro 7.4.12 (middleware), Service Worker API, xUnit, Playwright.

**Spec:** `Projetos/fisga/docs/superpowers/specs/2026-11-18-caching-design.md`.

## Global Constraints

- Default da API: `Cache-Control: private, no-store`; público só com metadata explícita.
- Nenhum HTML autenticado no Cache Storage.
- Sem Redis e sem CDN neste plano.
- Não enviar coordenadas, termos de busca, e-mail, cookie ou token ao Sentry.
- .NET 10 / C# nullable / `TreatWarningsAsErrors`; `dotnet format --verify-no-changes`.
- Astro 7.4.12; `astro check` e `npm run build` devem passar.
- Atualizar `packages.lock.json` e commitar junto com o `.csproj`.
- Manter os 250 testes de backend e 61 Playwright verdes.

## Review Focus

- Sessão expirada/logout deixando HTML de `/hoje` ou `/condicoes` no Cache Storage.
- Endpoint autenticado sem `no-store` sendo cacheado por um proxy/CDN futuro.
- Falha transitória do mar ficando cacheada por 20 min e escondendo a maré.
- Rajada de buscas iguais disparando múltiplas chamadas ao Open-Meteo.
- Normalização de termo/coordenada gerando colisão e devolvendo local errado.

`CachePolicy` deve montar os valores exatos:

```csharp
public sealed record CachePolicy(string HeaderValue)
{
    public static CachePolicy NoStore { get; } = new("private, no-store");

    public static CachePolicy Public(int maxAgeSeconds, int swr = 0) =>
        new(Montar("public", maxAgeSeconds, swr));

    public static CachePolicy Private(int maxAgeSeconds, int swr = 0) =>
        new(Montar("private", maxAgeSeconds, swr));

    private static string Montar(string visibilidade, int maxAgeSeconds, int swr) =>
        swr > 0
            ? $"{visibilidade}, max-age={maxAgeSeconds}, stale-while-revalidate={swr}"
            : $"{visibilidade}, max-age={maxAgeSeconds}";
}
```

O middleware usa `Response.OnStarting`, não sobrescreve header já definido e cai em `NoStore` quando não há metadata. Registrar com `app.UseMiddleware<CacheHeadersMiddleware>();` depois de `UseCors` e antes de `UseRateLimiter`.

## Correções da revisão final (2026-11-18)

A revisão de `f18205f..b6e4409` mudou estes comportamentos; o restante do plano continua válido.

1. **Erro não é cacheável:** API e middleware Astro forçam `private, no-store` quando o status é `>= 400`, independentemente da política do endpoint.
2. **TTL pelo valor devolvido:** condições, lua, busca e reverso reaplicam a política curta depois de qualquer `GetOrCreateAsync`, com `CancellationToken.None`; o tempo restante é calculado pela idade do cálculo para não estender o TTL sob tráfego.
3. **Expiração consistente:** `encerrarSessaoExpirada` limpa o estado privado e redireciona em `/meu-diario`, `/mapa` (401), `/registrar` (401) e `/boas-vindas`; `/mapa` 200 anônimo limpa o privado sem tirar o mapa público do ar; `/registrar` só limpa o rascunho em 401.
4. **Sentry:** `q`, `busca` e `termo` são sensíveis; query string usa allowlist e filtra chaves desconhecidas por padrão.
5. **SW testável:** `podeCachear`/`rotaPrivada` vivem em `web/public/sw-politicas.js` e têm teste Playwright direto.
6. **Logout preserva o offline:** `fisga-public-*` e `fisga-tiles-v1` sobrevivem; só `fisga-private-*` e `localStorage fisga:*` são apagados.
7. **Cardinalidade:** `MaximumPayloadBytes = 256 KB` e `MaximumKeyLength = 200`; o número de entradas fica limitado por chave/rate limit até a fase com L2.
